# Accountability Tracker Design

**Date:** 2026-05-17

## Goal

Build a native mobile accountability app where friends create private challenge groups, commit to daily goals, and hold each other accountable through check-ins, missed-check-in visibility, comments, and push notifications.

## Product Thesis

The MVP should be challenge-first. The primary product loop is social: users create or join private friend challenges and become active together. Personal tracking is included as a supporting mode using the same daily goal and check-in model, but it is not the main product surface.

The primary MVP success criterion is that friend groups get created and become active.

## Target Users

The MVP is for individual consumers who invite friends or small friend groups. It is not designed for coaches, managers, public communities, or enterprise accountability programs.

## Recommended Approach

Use a challenge-based private group app with personal tracker fallback.

This keeps the experience focused on group activation while still allowing users to track personal goals outside a group. The app should avoid splitting the first version into two equal products. Group challenges are the main surface; personal tracking is a secondary path.

## Core Product Loop

1. User signs up and creates a profile.
2. User creates or joins a private invite-only challenge.
3. User creates daily goals inside the challenge.
4. User configures a daily deadline for each goal.
5. App reminds the user before the deadline.
6. User submits a daily status check-in with an optional note.
7. Group feed shows completions, skips, and missed check-ins.
8. Group members can respond with lightweight comments.
9. Missed check-ins are marked automatically and trigger group notifications.

## MVP Features

### Account And Onboarding

- Email signup.
- Profile with display name and timezone.
- Create a private challenge.
- Join a private challenge through an invite link or invite code.
- Optional entry into personal tracker mode.

### Challenge Groups

- Create a private invite-only challenge.
- Configure challenge name, description, start date, and optional end date.
- Invite friends.
- View member list.
- View challenge detail and feed.
- Owner can edit basic challenge settings.

### Goals

- Users create their own goals inside a challenge.
- Users can create private personal tracker goals outside a challenge.
- MVP supports daily cadence only.
- Each goal has a configurable daily deadline.
- Each deadline is interpreted against the goal owner's timezone.
- Goals can be archived or paused.

### Check-Ins

- Each active goal expects one check-in per local day.
- Required status for user-submitted check-ins.
- Optional note.
- MVP statuses are `done`, `skipped`, and `missed`.
- `done` and `skipped` are submitted by the user.
- `missed` is generated by the system after the deadline if no check-in exists.
- Duplicate check-ins for the same goal and local date are prevented.

### Social Feed

- Group feed shows completed, skipped, and missed check-ins.
- Group members can comment on feed items.
- Personal tracker activity remains private.
- MVP does not include full chat.

### Push Notifications

- Reminder before a user's configured deadline.
- Missed-check-in notification to relevant challenge members.
- Comment notification to the feed item owner.
- Completion notifications should be quiet by default or configurable to prevent notification noise.

## Technical Architecture

### Client

- React Native with Expo.
- Expo push notifications.
- Native mobile app first.

### Backend

- Supabase Auth.
- Supabase Postgres.
- Supabase Realtime where useful for feed freshness.
- Supabase scheduled functions or cron-compatible jobs for missed-check-in generation and reminder orchestration.

### Storage

No file storage is required for MVP because proof photos and videos are out of scope.

## Product Rules

- Challenges are private and invite-only.
- Challenge groups may be ongoing or time-boxed.
- A challenge with one member is valid, but the app should encourage inviting friends.
- Personal tracker goals are private unless they are attached to a challenge.
- Missed check-ins are visible in the related challenge feed.
- Missed check-ins notify challenge members.
- Users can have multiple active goals with different deadlines.
- Timezone changes affect future local-day calculations, not historical records.
- Owner departure from a challenge should require ownership transfer or challenge archival.

## MVP Non-Goals

- Public groups.
- Discoverable communities.
- Coach or manager dashboards.
- Photo or video evidence.
- Rich gamification, rankings, or punishments.
- Complex analytics.
- Full group chat.
- Multi-cadence goals beyond daily.
- Marketplace or challenge discovery.

## Edge Cases

- User joins challenge after start date.
- User changes timezone.
- User changes deadline time.
- User has multiple goals with different deadlines.
- App is not opened before deadline.
- Push token expires or changes.
- Challenge has only one member.
- Owner leaves challenge.
- Goal is paused or archived.
- Duplicate check-in is attempted.
- Missed-check-in job runs late or retries.
- User submits close to the deadline while the missed-check-in job is running.

- Database constraint tests for duplicate check-ins.
- Integration tests for challenge membership permissions.

- Review pass before each milestone expands scope.

## Implementation Defaults

- Use email authentication first. Phone authentication can be added later if onboarding data shows it is needed.
- Send the default reminder one hour before the user's goal deadline.
- Use comments for MVP responses. Reactions can be added later if comment friction is too high.
- Keep challenge settings owner-only for MVP.
- Invite links should not expire automatically in MVP, but owners can regenerate the invite code.
